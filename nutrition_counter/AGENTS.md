# Инструкции для агентов

## Источники требований

Перед изменениями прочитайте:

1. `spec/product/product.md` — задача пользователя, сценарии, границы версии и критерии приёмки.
2. `spec/tech/architecture.md` — текущий стек, структура и технические ограничения.
3. `spec/tech/rag.md` — граница между демонстрационными данными и будущей интеграцией BM25/LLM.
4. `README.md` — запуск проекта; `CHANGE_HISTORY.md` — история изменений.

Пустой или отсутствующий раздел спецификации не означает, что соответствующий компонент реализован. Отличайте текущее поведение от планов. При противоречии файлов с явным запросом пользователя следуйте запросу и синхронизируйте документацию.

## Порядок работы по SDD

1. Определите затрагиваемые требования и критерии приёмки.
2. Если меняются сценарий, границы версии, стек или архитектура, сначала актуализируйте соответствующий SDD, затем реализацию. При документировании уже выполненной работы сверяйте SDD с кодом.
3. Вносите изменения в рамках задачи. Сохраняйте пользовательские изменения в рабочем дереве.
4. Проверьте затронутые сценарии и команды запуска. Не представляйте непроведённые проверки как успешные.
5. Обновите README при изменении запуска или поведения и добавьте запись в CHANGE_HISTORY с датой, изменениями и результатами проверки.

## Технологии и ограничения

* Текущий интерфейс: HTML5, CSS3 и обычный браузерный JavaScript без фреймворков и сборки.
* Локальный сервер: Node.js 18+, ES modules (`server.mjs`), только встроенные модули. Установка пакетов не требуется.
* Сохраняйте этот стек для изменений макета. Добавляйте зависимости или сборку только при обоснованной необходимости задачи; фиксируйте причину и запуск в техническом SDD и README.
* Первая версия использует только явно обозначенные mock-ответы и вымышленные статьи. Не выдавайте их за результаты BM25, реальные публикации или ответы LLM.
* Не добавляйте API, базу данных, авторизацию, хранение истории или дневник калорий без соответствующего изменения требований.
* Пользовательский текст вставляйте через `textContent` или эквивалентное безопасное создание DOM, а не через `innerHTML`.
* Сохраняйте русскоязычный интерфейс, адаптивность, управление клавиатурой и поддержку `prefers-reduced-motion`.
* При добавлении публичных файлов обновляйте явный список разрешённых файлов в сервере. Не открывайте доступ ко всему репозиторию или файлам конфигурации.

## Запуск и проверка

Из корня репозитория `Fat-counter`:

```powershell
node nutrition_counter/frontend/server.mjs
node --check nutrition_counter/frontend/app.js
node --check nutrition_counter/frontend/server.mjs
git diff --check
```

Сервер запускайте в отдельном терминале: он работает до `Ctrl+C`. Адрес по умолчанию — `http://localhost:3000`.

При изменениях интерфейса проверяйте критерии из продуктового SDD: пустой ввод, отправку, блокировку повторного запроса, получение ответа и источников, открытие карточки, сброс во время загрузки, узкий экран и клавиатуру. Автоматизированного тестового набора пока нет. Проверки синтаксиса и HTTP не заменяют визуальную проверку; если браузер недоступен, укажите это в отчёте.
