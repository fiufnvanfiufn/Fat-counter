## Текущее состояние
Адаптивный интерфейс с дневником питания, статистикой калорий/БЖУ, избранным и профилем. **FastAPI + SQLite** хранят данные и раздают фронтенд. Чат выполняет локальный **BM25-поиск** по 30 русскоязычным конспектам `D01`–`D30` материалов WHO, NHS, Harvard Nutrition Source, NIDDK и Food Standards Agency. Gemini генерирует ответ по найденным фрагментам либо отказывается, если ответа в них нет. Без ключа доступны найденные выдержки. Для сдачи подготовлен benchmark: 10 обычных вопросов с эталонами и 5 ловушек.

«База знаний» — отдельный каталог всех 30 конспектов с поиском по ID, заголовку и тексту. Он доступен из бокового меню и верхней кнопки независимо от избранного. Статьи о сахаре, белке и общих принципах питания дополнены проверенными сведениями; короткий запрос вроде «белок» трактуется как просьба дать обзор темы. Если подтверждена только часть широкого вопроса, помощник отвечает на эту часть и обозначает ограничения.

## Локальный запуск

### Windows / PowerShell

Требуется **Python 3.10+**. Команды выполняются из корня репозитория `Fat-counter`. Установка зависимостей нужна при первом запуске и после изменения `requirements.txt`.

```powershell
python -m venv nutrition_counter/backend/.venv
.\nutrition_counter\backend\.venv\Scripts\python.exe -m pip install -r nutrition_counter/backend/requirements.txt
.\nutrition_counter\backend\.venv\Scripts\python.exe -m uvicorn main:app --app-dir nutrition_counter/backend --host 127.0.0.1 --port 8000
```

Откройте **[http://localhost:8000](http://localhost:8000)**. Остановка — `Ctrl+C`. Без API-ключа уже работает поиск с выдержками из конспектов. Старый Node.js-сервер на порту 3000 раздаёт только файлы, не предоставляет API и для рабочего приложения не используется.

Swagger UI: **[http://localhost:8000/docs](http://localhost:8000/docs)**.

После обновления кода или корпуса остановите свой сервер через `Ctrl+C`, повторите команду запуска и обновите страницу через `Ctrl+F5`. Без перезапуска в памяти останется прежний поисковый индекс, а браузер может использовать старый JavaScript. Если порт 8000 занят уже работающим сервером, сначала остановите его в том терминале, где он запущен.

### Gemini и запуск у преподавателя

В этой учебной копии `backend/.env` уже заполнен предоставленным владельцем ключом. По его явному запросу файл входит в передаваемый проект и разрешён для включения в Git, чтобы преподаватель мог запустить приложение с теми же настройками. Ключ доступен читателям такой копии и использует общую квоту проекта. Само значение не выводится в документации, интерфейсе или ответах API.

Для запуска достаточно установить зависимости и выполнить команду сервера выше. Рабочая модель — `gemini-3.1-flash-lite`; с ней проверен настоящий ответ API.

Если вы используете собственный ключ, создайте его в [Google AI Studio](https://aistudio.google.com/api-keys). Для бесплатного использования выбирайте проект Free tier без подключённого биллинга. Если файл настроек отсутствует, создайте его без перезаписи существующего:

```powershell
if (-not (Test-Path nutrition_counter/backend/.env)) {
    Copy-Item nutrition_counter/backend/.env.example nutrition_counter/backend/.env
}
```

Откройте `nutrition_counter/backend/.env` в редакторе, замените `GEMINI_API_KEY` своим значением и перезапустите сервер. Пример формата:

```dotenv
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-3.1-flash-lite
GEMINI_TIMEOUT_SECONDS=30
```

Переменные окружения терминала имеют приоритет над `.env`. Поле `configured` в [статусе чата](http://localhost:8000/api/chat/status) означает наличие ключа; будущую доступность модели и остаток квоты оно не проверяет.

На дату проверки модели заявлен [Free tier](https://aistudio.google.com/docs/pricing#gemini-3.1-flash-lite), но лимиты и доступ зависят от проекта и [поддерживаемого региона](https://aistudio.google.com/docs/available-regions); России в опубликованном списке нет. Приложение не включает биллинг и не переходит на платную модель автоматически, но не может определить тариф уже созданного ключа. На бесплатном тарифе Google может использовать запросы для улучшения продуктов. В обычном чате отправляются **вопрос и найденные конспекты**. Только после явного нажатия «Спросить ассистента о рационе» дополнительно передаются записанные блюда, их итоги и заданные цели калорий/белка. Имя, возраст, рост, вес и пищевые ограничения в этот снимок не входят.

Ошибки ключа, квот или сети отображаются как ошибки, без подмены заготовленным ответом. Проверенный запрос не гарантирует доступность сервиса и квоты при каждом последующем запуске.

## API endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/profile` | Получить профиль пользователя |
| PUT | `/api/profile` | Обновить профиль |
| GET | `/api/meals` | Список приёмов пищи |
| POST | `/api/meals` | Добавить блюдо |
| DELETE | `/api/meals/{id}` | Удалить блюдо |
| DELETE | `/api/meals` | Очистить весь дневник |
| GET | `/api/sources` | Список источников |
| GET | `/api/knowledge?q=...` | Каталог 30 индексируемых документов с необязательным поиском |
| GET | `/api/sources/{id}` | Получить источник |
| PATCH | `/api/sources/{id}/bookmark` | Переключить избранное |
| GET | `/api/foods?q=...` | Поиск по базе продуктов |
| GET | `/api/chat/status` | Режим настройки Gemini и размер корпуса |
| POST | `/api/chat` | BM25 → выдержки; при ключе — Gemini; `scope=diary` явно включает снимок дневника |

## Возможности приложения

* **Чат с источниками:** BM25-поиск, генерация по контексту при наличии ключа, режим поиска без LLM, сообщения об отсутствии материалов и ошибках. Поддерживаются `Enter` / `Shift+Enter`, отмена при новом разговоре и повтор вопроса после ошибки.
* **Проверяемые материалы:** Карточки содержат издателя, ссылку на оригинал, локальный конспект и найденные выдержки. Конспекты — краткие редакторские пересказы, а не полные исходные статьи. Дата проверки конспекта не является датой публикации оригинала.
* **База знаний:** Отдельный каталог `D01`–`D30` с поиском, чтением конспекта, оригинальной ссылкой и добавлением в избранное. При сбое загрузки доступны сообщение и повтор.
* **Дневник питания и категория приёмов пищи:** Учёт блюд по 4 приёмам пищи: 🌅 Завтрак, ☀️ Обед, 🌙 Ужин, 🍏 Перекусы.
* **База продуктов (Dataset):** Поиск и выбор готовых блюд из предустановленной базы знаний или добавление собственного блюда с калориями и БЖУ.
* **Статистика и автоматический перерасчёт:** Пересчёт калорий, оставшегося лимита и прогресс-баров БЖУ по дневнику. Недельный график пока содержит демонстрационные значения; полноценная история по датам не реализована.
* **Анализ записанного рациона:** Кнопка в статистике открывает чат и запрашивает анализ фактических записей сервера. Перед отправкой показано, какие данные получит Gemini. Вывод включает число записей и суммы; это все записанные блюда, а не автоматически полный текущий день. Передаются последние 50 записей, суммы считаются по всему дневнику. Сравнение идёт с целями, заданными пользователем, а не с рассчитанной медицинской нормой. Для пустого дневника выводится подсказка без вызова LLM.
* **Избранные материалы:** Добавление источников из чата в избранное, фильтрация по категориям (статьи, советы, рецепты) и удаление.
* **Профиль и цели:** Персональные настройки пользователя (возраст, вес, рост, дневной калораж, белки и пищевые ограничения) с сохранением на сервере.
* **Адаптивная навигация:** Выдвижное боковое меню для мобильных устройств, обработка клавиши `Escape` и мобильных безопасных зон (`env(safe-area-inset-bottom)`).

## Проверки

Из корня репозитория после установки зависимостей:

```powershell
.\nutrition_counter\backend\.venv\Scripts\python.exe -m unittest discover -s nutrition_counter/backend/tests -v
node --test nutrition_counter/frontend/tests/chat.test.mjs
node --check nutrition_counter/frontend/app.js
git diff --check
```

Для JavaScript-проверок нужен Node.js 18+. Тесты Gemini используют подменный HTTP-транспорт и не расходуют квоту. Они не подтверждают живой доступ к API: он проверяется отдельно с вашим ключом. Расширение корпуса описано в [RAG SDD](spec/tech/rag.md).

## Учебный benchmark: 30 документов, 10 + 5 вопросов

Набор подготовлен заранее: [замороженный корпус v1 D01–D30](benchmark/corpus-v1.json), [15 вопросов с эталонами](benchmark/questions.json) и [порядок проверки](benchmark/README.md). У обычных вопросов указаны релевантные ID и ожидаемые факты; у ловушек ответа в корпусе нет, поэтому ожидается отказ без выдуманных сведений. Эталоны не передаются модели и не участвуют в поиске. Рабочий корпус `backend/knowledge/articles.json` развивается отдельно, чтобы исправления не меняли основания старых отчётов.

Из корня репозитория:

```powershell
.\nutrition_counter\backend\.venv\Scripts\python.exe nutrition_counter/benchmark/run.py
```

По умолчанию это воспроизведение офлайн-поиска v1: `benchmark/corpus-v1.json`, вес заголовка 0. Оно не обращается к Gemini и не подтверждает качество ответов или отказов LLM. Для сравнения с текущим рабочим корпусом и усилением заголовков сохраняйте отдельный отчёт:

```powershell
.\nutrition_counter\backend\.venv\Scripts\python.exe nutrition_counter/benchmark/run.py --corpus nutrition_counter/backend/knowledge/articles.json --title-weight 2 --output nutrition_counter/benchmark/results/current-offline
```

Для отдельного живого прогона v1 с текущим серверным ключом:

```powershell
.\nutrition_counter\backend\.venv\Scripts\python.exe nutrition_counter/benchmark/run.py --live
```

Живой прогон расходует квоту API. Ответы сопоставляют с эталонами вручную по критериям в инструкции; автоматические показатели поиска нельзя выдавать за проверку всех фактов ответа.
