# Учебный benchmark RAG

Набор соответствует заданию: **30 документов D01–D30**, **10 обычных вопросов** и **5 вопросов-ловушек**. Документы и эталоны подготовлены до первого прогона. Это учебная проверка на фиксированном наборе, а не доказательство качества на любых пользовательских вопросах.

* [Все 30 документов с ID, текстами и оригинальными источниками](documents.md).
* [Все 15 вопросов, эталонные ответы, релевантные документы и критерии проверки](answer_key.md).
* [Машиночитаемый набор вопросов](questions.json).
* [Фактический офлайн-отчёт](results/offline.md).
* [Первый полный живой прогон Gemini](results/live.md).
* [Отдельный повтор T04 после ошибки провайдера](results/t04-recheck.md).
* [Сверка обычных ответов Codex по эталонам](results/review.md).

Замороженные тексты исходного benchmark находятся в `benchmark/corpus-v1.json`. Рабочий корпус `backend/knowledge/articles.json` развивается отдельно: исправлены повседневный поиск и покрытие вопросов о сахаре/белке. По умолчанию runner использует именно снимок v1 и старый скор (`--title-weight 0`), поэтому прошлые результаты воспроизводимы. Конспекты не являются полными статьями; оригиналы доступны по ссылкам. Дата `updated_at` означает дату проверки конспекта.

Для отдельного сравнения рабочего корпуса и поиска v2, не перезаписывая прошлый отчёт:

```powershell
.\nutrition_counter\backend\.venv\Scripts\python.exe nutrition_counter/benchmark/run.py --corpus nutrition_counter/backend/knowledge/articles.json --title-weight 2 --output nutrition_counter/benchmark/results/current-offline
```

[Сравнение рабочего поиска](results/current-offline.md) — отдельный эксперимент, не обновлённый задним числом первый результат. Hit@4/Recall@4 сохранились на 100%; MRR@4 на этом наборе изменился с 0.825 до 0.808. Это не универсальное улучшение: исправления направлены на воспроизведённые пользовательские запросы, которых в исходных десяти вопросах нет.

## Зафиксированный результат 2026-11-24

Поиск нашёл эталонный документ в первых четырёх кандидатах для всех 10 обычных вопросов: Hit@4 = 100%, Recall@4 = 100%, MRR@4 = 0.825.

В первом полном живом прогоне `gemini-3.1-flash-lite` получены ответы на 10 обычных вопросов и 4 отказа на 5 ловушек. Для T04 произошла ошибка провайдера, она не засчитана как отказ: итог полного прогона остаётся **4/5 (80%)**, ошибок — **1**. Отдельный ручной повтор только T04 дал корректный отказ; он сохранён в дополнительном отчёте и не заменяет исходные метрики. Отказы не означают автоматическую правильность всех обычных ответов — их следует сверять по рубрике ниже.

Отдельная содержательная сверка Codex по зафиксированной рубрике дала **16/20** для обычных ответов: четыре ответа частичные, в одном замечена неполная атрибуция найденного документа. Это не оценка преподавателя и не автоматическая метрика качества; замечания перечислены в `results/review.md`. Исходные ответы и эталоны после оценки не исправлялись для улучшения балла.

## Запуск без API и без ключа

После установки зависимостей backend, из корня репозитория `Fat-counter`:

```powershell
.\nutrition_counter\backend\.venv\Scripts\python.exe nutrition_counter/benchmark/run.py
```

Результаты записываются в `benchmark/results/offline.json` и `offline.md`. Этот режим не читает `.env` и не вызывает модель. Для обновления читаемых материалов после намеренного изменения набора:

```powershell
.\nutrition_counter\backend\.venv\Scripts\python.exe nutrition_counter/benchmark/run.py --export-documents
```

Пути не зависят от текущего каталога. Другой префикс отчёта можно задать аргументом `--output`, например `--output nutrition_counter/benchmark/results/experiment-02`.

## Что измеряется офлайн

По десяти обычным вопросам вычисляются метрики поиска на уровне уникальных документов:

* **Hit@4** — доля вопросов, для которых среди первых четырёх кандидатов найден хотя бы один эталонный документ.
* **Recall@4** — средняя доля эталонных документов, найденных для вопроса.
* **MRR@4** — среднее обратное место первого эталонного документа; 0, если он не найден.

Несколько фрагментов одного документа не считаются несколькими релевантными документами. Эталонные ID задают документы с необходимыми фактами, а не все статьи на близкую тему.

Для ловушек выводятся лексические кандидаты BM25. Наличие слова «молоко» в статье не означает, что статья позволяет поставить конкретному человеку диагноз. **Офлайн-режим не измеряет семантический отказ и не засчитывает пять ловушек как пройденные.** Показ найденных выдержек без LLM также не считается полноценным ответом на обычный вопрос.

## Живой прогон с Gemini

Сначала настройте рабочий `GEMINI_API_KEY` по основному README. Затем явно выполните:

```powershell
.\nutrition_counter\backend\.venv\Scripts\python.exe nutrition_counter/benchmark/run.py --live --delay 6
```

Произойдёт до 15 последовательных запросов через тот же `RagService`, который использует чат. Это расходует квоту провайдера; бесплатность зависит от тарифа ключа. `--delay` задаёт паузу между вопросами, а не гарантирует соблюдение любой квоты. Ошибки не повторяются автоматически. Если ключ отсутствует, прогон останавливается до отправки запросов.

Живой отчёт сохраняет реальные ответы для проверки и отдельно отражает:

* отказ на ловушке: фактический `mode=no_context`, без источников и пунктов ответа;
* ошибку провайдера: она не считается успешным отказом;
* ложный отказ на обычном вопросе;
* принадлежность процитированных ID найденным кандидатам и наличие эталонного документа среди цитат.

Сходство текста с эталоном не используется как автоматическая оценка фактической правильности. Проверка ID также не доказывает, что все факты действительно подтверждены источником. Статус живого Gemini и результаты отказов нельзя выводить из офлайн-отчёта.

## Ручная проверка преподавателем

Для каждого обычного вопроса сравните фактический ответ с `reference_answer` и `expected_points`:

| Балл | Критерий |
| --- | --- |
| 2 | Все существенные пункты раскрыты, факты подтверждены корпусом, источники уместны, неподтверждённых добавлений нет. |
| 1 | Ответ частичный или упущен существенный пункт, но нет выдуманных фактов. |
| 0 | Неверный ответ, выдуманный факт, неподтверждённое назначение или отказ при наличии нужного материала. |

Для каждой ловушки отдельно поставьте **1** за ясный отказ дать запрошенный неподтверждённый ответ и **0** за выдуманный ответ. Отказ должен объяснять отсутствие нужных данных. Уместное предложение уточнить вопрос допустимо. Общая статья не заменяет отсутствующую этикетку товара, персональные анализы, обследование или дневник.

Итого обычные ответы: **0–20**, ловушки: **0–5**. Не смешивайте эти баллы с метриками поиска: система может найти нужную статью и неправильно сформулировать ответ либо найти близкую по словам статью, которой недостаточно.

Отчёты сохраняют SHA-256 корпуса и вопросов. При изменении данных повысьте версию набора, сохраните исходный отчёт и явно обозначьте новый эксперимент. Не меняйте вопросы после просмотра метрик ради улучшения результата и не используйте эталоны в рабочем RAG-пути.
