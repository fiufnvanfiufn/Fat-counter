# Технический SDD: архитектура

## Статус и назначение

На 2026-10-09 реализована первая версия — локальный интерактивный макет чата по `../product/product.md`. Приложение демонстрирует сценарий вопрос → ожидание → заготовленный ответ → карточки источников. Реального поиска и генерации нет.

## Использованный стек

| Слой | Технологии | Назначение |
| --- | --- | --- |
| Разметка | HTML5, семантические элементы, нативный `dialog` | Главный экран, чат, форма, окно описания источника |
| Оформление | CSS3, Flexbox, Grid, media queries, CSS animations | Адаптивный макет, состояния элементов, индикатор ожидания |
| Логика интерфейса | Vanilla JavaScript, DOM API, `setTimeout` | Отправка вопроса, выбор mock-ответа, источники, сброс разговора |
| Иконки | Встроенные SVG symbols | Локальные иконки без внешнего сервиса |
| Локальная раздача | Node.js 18+, ES modules; `node:http`, `node:fs/promises`, `node:url`, `node:path` | HTTP-сервер статических файлов |
| Метаданные запуска | `package.json` | Требование Node.js и необязательный npm-скрипт `start` |

React, TypeScript, Vite и внешние библиотеки не используются. Сборки, установки зависимостей, внешних шрифтов и сетевых запросов к API нет. Выбран простой стек, достаточный для фронтенд-макета.

## Структура

```text
nutrition_counter/
  AGENTS.md                 # правила для агентов
  CHANGE_HISTORY.md         # история изменений и проверок
  README.md                 # пользовательский запуск
  frontend/
    index.html              # разметка и SVG-иконки
    styles.css              # оформление и адаптивность
    app.js                  # mock-данные и логика DOM
    server.mjs              # локальный HTTP-сервер
    package.json            # без dependencies
  spec/
    product/product.md      # продуктовый контракт
    tech/architecture.md    # текущая архитектура
    tech/rag.md             # текущий mock и будущая интеграция
```

## Состояния и поток данных

1. Начальный экран содержит четыре подсказки и поле вопроса. Отправка пустого или пробельного ввода недоступна.
2. Отправка кнопкой, `Enter` или подсказкой добавляет сообщение пользователя. `Shift+Enter` вводит новую строку.
3. На время демонстрационной задержки 1200 мс ввод и отправка блокируются; отображается индикатор ожидания. Повторный запрос игнорируется.
4. `selectMock` выбирает один из четырёх тематических ответов по ключевым словам либо общий ответ с явным объяснением ограничения. Это не анализ запроса нейросетью.
5. Ответ содержит текст, список и две карточки источников. Карточка открывает описание вымышленной статьи в `dialog`.
6. «Новый разговор» сбрасывает сообщения и отменяет ожидающий ответ. Счётчик поколения защищает от добавления устаревшего ответа после сброса.

История существует только в DOM текущей страницы. Перезагрузка очищает её. `localStorage`, cookies, база данных и серверное хранение не используются.

## Локальный сервер

Из корня репозитория:

```powershell
node nutrition_counter/frontend/server.mjs
```

Сервер слушает `127.0.0.1:3000`; порт задаётся переменной окружения `PORT`. Публикуются только `index.html`, `styles.css` и `app.js`; путь `/` возвращает `index.html`. Поддерживаются `GET` и `HEAD`. Другие методы возвращают 405, неизвестные файлы — 404. Ответы имеют соответствующий MIME-тип, `Cache-Control: no-store` и `X-Content-Type-Options: nosniff`.

Сервер предназначен для локального просмотра, не является backend для RAG. Статические файлы можно разместить на статическом хостинге; конфигурация публикации в текущую версию не входит.

## Интерфейс и безопасность

Светлая палитра с зелёными акцентами, боковое меню и центральная область чата. CSS содержит адаптивные правила, в том числе мобильное меню при ширине до 760 px. Используются подписи полей и кнопок, видимый фокус, `aria-live`, `aria-busy`, клавиатурное закрытие диалога и уменьшение анимации через `prefers-reduced-motion`.

Вопросы отображаются через `textContent` и не интерпретируются как HTML. Они не отправляются во внешние сервисы. Демонстрационные материалы обозначены и в коде, и в интерфейсе.

## Проверка

Критерии сценария перечислены в продуктовом SDD. Минимальные проверки: синтаксис `app.js` и `server.mjs` через `node --check`, HTTP-доступность страницы и ресурсов, ручное прохождение сценариев на широком и узком экранах. Автоматизированный тестовый набор и CI пока не добавлены. Фактически выполненные проверки и их ограничения фиксируются в CHANGE_HISTORY.
