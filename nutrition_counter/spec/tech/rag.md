# Технический SDD: BM25 и RAG

## Текущее состояние

BM25 и LLM не подключены. Корпуса реальных документов, индекса, API поиска и генерации в репозитории нет. Node.js используется исключительно для локальной раздачи файлов интерфейса.

В `frontend/app.js` находятся:

* `MOCK_RESPONSES` — подготовленные ответы с полями `intro`, `items`, `end`, `sources`.
* `MOCK_SOURCES` — вымышленные статьи с полями `title`, `description`.
* `selectMock(question)` — выбор ответа по ключевым словам для замены свинины, белка, обеда и перекуса; для других запросов возвращается общий демонстрационный ответ.

Массив `sources` связывает ответ с идентификаторами демонстрационных статей. Задержка 1200 мс имитирует ожидание. Никакого ранжирования, оценки релевантности или обращения к модели при этом не выполняется. Названия и описания не являются цитатами или ссылками на реальные публикации.

## Целевой сценарий будущей интеграции

Согласно продуктовому замыслу, система должна находить текстовые статьи алгоритмом BM25 и использовать найденные материалы для ответа LLM. Интерфейс должен показывать относящиеся к ответу источники.

Это план, а не реализованный контракт. Язык backend, библиотека BM25, модель, поставщик API, хранилище, формат документов и параметры поиска пока не определены.

Перед реализацией следующего этапа необходимо зафиксировать в SDD:

1. Корпус статей, их происхождение, стабильные идентификаторы и доступный пользователю текст или URL.
2. Подготовку документов и индексирование BM25: токенизацию, язык, разбиение текста и обновление индекса.
3. Контракт запросов и ответов между интерфейсом и backend, связь ответа с найденными документами.
4. Поведение при отсутствии релевантных документов, сбоях поиска/модели и отмене запроса.
5. Правила работы с пользовательскими вопросами, конфигурацией и секретами. Ключи API не должны попадать в браузерные файлы или репозиторий.
6. Критерии проверки поиска и того, что ответ опирается на показанные источники.

При замене mock-данных обновите продуктовый SDD, архитектуру, README и историю изменений. До подтверждённой интеграции сохраняйте явную маркировку демонстрационного режима.
